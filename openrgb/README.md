# OpenRGB setup (Linux only)

Everything needed to get the RGB lighting of this PC (Gigabyte B550M AORUS ELITE, HyperX Fury RGB RAM,
HyperX Pulsefire mouse) working again on a fresh Linux install, with instant colour-profile launchers.

**Not part of the Stow setup.** `stow .` ignores this folder (see `../.stow-local-ignore`) and nothing here runs
automatically. On a machine where you want it, run the installer yourself:

```shell
./openrgb/setup.sh            # install: symlinks + user services; asks before every sudo step
./openrgb/setup.sh status     # what is installed / missing (incl. uncommitted profiles)
./openrgb/setup.sh launchers  # add menu entries for new profiles, remove those of deleted profiles
./openrgb/setup.sh --help
```

Everything is **symlinked** into place, so `git pull` updates the live setup (restart the services to pick up
script changes: `systemctl --user restart openrgb-server openrgb-profile`). Files that were already in the way are
moved to `~/.local/state/openrgb-setup/backup-<timestamp>/`.

## What it gives you

| Where | What |
|---|---|
| Start menu: **OpenRGB: <Profile>** (one per profile), **OpenRGB** | one-click profile switch (~0.35 s) / the normal GUI |
| Notification after saving a profile in the GUI | reminder if it is not committed to the dotfiles yet or has no menu entry |
| Login + after every resume from suspend | the last-chosen profile is re-applied automatically |

## Files

| Repo path | Linked to | Purpose |
|---|---|---|
| `bin/openrgb-run` | `~/.local/bin/` | finds OpenRGB (`$OPENRGB_BIN`, PATH, `~/Applications/*.AppImage`, Flatpak); every other script calls OpenRGB through it |
| `bin/openrgb-set-profile` | `~/.local/bin/` | `openrgb-set-profile <name>`: loads a profile instantly, remembers it, shows a transient notification |
| `bin/openrgb-sdk.py` | `~/.local/bin/` | tiny client for OpenRGB's SDK server (load a profile, wait until ready) |
| `bin/openrgb-apply-profile.sh` | `~/.local/bin/` | long-running: applies the last profile at login and after resume (watches logind `PrepareForSleep`) |
| `systemd/openrgb-server.service` | `~/.config/systemd/user/` | headless OpenRGB server on port 6743 (~30 MB, ~2 % of one core). This is why switching is instant: no re-detection |
| `systemd/openrgb-profile.service` | `~/.config/systemd/user/` | runs `openrgb-apply-profile.sh` |
| `bin/openrgb-profile-reminder` | `~/.local/bin/` | report-only: notification listing profiles that are not committed or have no launcher |
| `systemd/openrgb-profiles-watch.path` + `.service` | `~/.config/systemd/user/` | runs the reminder whenever the profiles folder changes |
| `applications/*.desktop` | `~/.local/share/applications/` | menu entries: the GUI plus one per profile (each has `X-OpenRGB-Profile=<name>`, generated by `setup.sh launchers`) |
| `icons/openrgb.png` | `~/.local/share/icons/hicolor/128x128/apps/` | icon (taken from the AppImage) |
| `fontconfig/fonts.conf` | `~/.config/openrgb-fontconfig/` | workaround, see Gotchas. Used automatically by `openrgb-run` when present |
| `config/profiles/` | `~/.config/OpenRGB/profiles` (whole directory) | `purple`, `orange`, `off`. Profiles saved from the OpenRGB GUI land here, so just commit them |
| `config/Configuration.json` | `~/.config/OpenRGB/Configuration.json` | per-device settings (zone sizes, colour-order calibration) |
| `setup.sh` | | the installer |

The *last chosen profile* is runtime state in `~/.config/openrgb-current-profile` (not tracked; defaults to `purple`).

### System-level steps (sudo, done by `setup.sh` after asking)

| Step | Why |
|---|---|
| `/etc/udev/rules.d/60-openrgb.rules` | access to the devices without root. **Generated by OpenRGB itself** (`openrgb --print-udev-rules`); not stored here, the repo no longer contains a ready-made copy for 1.1 |
| `/etc/modules-load.d/openrgb.conf` (`i2c-dev` + `i2c-piix4` on AMD / `i2c-i801` on Intel) | I2C/SMBus access for RAM and some boards |
| kernel parameter `acpi_enforce_resources=lax` | only if the SMBus is blocked (see Gotchas). `rpm-ostree kargs` on Bazzite/Fedora Atomic, GRUB edit elsewhere. Needs a reboot |

## Moving to a new machine (e.g. Bazzite + KDE)

1. Install OpenRGB: the setup script offers to download the 1.1 AppImage; the Flatpak (`org.openrgb.OpenRGB`) or a
   distro package also work (`openrgb-run` finds all of them). Needs `systemd --user`, `python3`, `flock`,
   `dbus-monitor`, `notify-send` (all standard).
2. `git clone` the dotfiles, then `./openrgb/setup.sh` and answer the questions.
3. Reboot (udev rules / kernel parameter), open **OpenRGB** once and check that every device shows up.

> Written and tested on Zorin OS 18 (Ubuntu 24.04 base, GNOME) only. The Bazzite/KDE and Flatpak code paths
> (`rpm-ostree kargs`, Flatpak config dir) are untested; check them on the first real run.

## Gotchas this setup works around

- **GUI segfault in `libfontconfig`** (both Flatpak and AppImage, with the stock fontconfig rules on Zorin). With the
  minimal `fonts.conf` the GUI is fine. Harmless elsewhere; delete `~/.config/openrgb-fontconfig/` if not needed.
- **RAM invisible / "I2C interfaces failed to initialize"**: on this board the kernel logged
  `ACPI Warning: SystemIO range 0xB00-0xB08 conflicts with OpRegion` and refused to create the SMBus adapter.
  `acpi_enforce_resources=lax` fixes it. `setup.sh` recommends it when it finds that message in the kernel log.
- **Motherboard missing in OpenRGB (controller `048d:5702`)**: another program was holding the USB device
  (`linuity-daemon`, a root service from the Linuity project). Remove such tools. Check with
  `readlink /sys/bus/usb/devices/1-10:1.0/driver` (should end in `usbhid`) and
  `sudo fuser -v /dev/bus/usb/001/003`. To reset the controller:
  `echo 0 | sudo tee /sys/bus/usb/devices/1-10/authorized; sleep 1; echo 1 | sudo tee /sys/bus/usb/devices/1-10/authorized`
  (bus/port `1-10` is specific to this machine; find yours with `lsusb`).
  `./openrgb/setup.sh status` reports any RGB controller held like this (report only, it changes nothing).
- **LEDs reset to orange at boot / after resume**: the controller's own stored default; the services re-apply the
  chosen profile afterwards. Boot-time colour can only be changed in the BIOS.
- **Case LED colours uneven** (bottom strip rose, 4 spots red): the case fans and strips are wired in *parallel* on
  `D_LED2` (every part shows the same LED indices) and the strip has weak/dead blue emitters, so no single colour
  fits all. Fix = hardware: move the strips to the free `D_LED1` header, then tune each header separately (strip
  ~`(20,0,255)`, fans `(166,0,255)` looked right). Channel order is fine (`GRB`).
- **Starting `openrgb --profile X` is slow (~13 s)**: ~8 s is probing the RAM slots on every start; that is why the
  resident server exists.

## Adding a profile / launcher

1. In the OpenRGB GUI set the colours and press **Save Profile** (it is written into `config/profiles/`).
   In the **Profile Editor** that opens, tick **Include In Profile** for every device (or **Select All**):
   for a new profile they start unticked, and saving like that writes an empty profile (only `profile_name`).
2. A notification reminds you that the profile is not committed and has no menu entry yet.
3. Run `./openrgb/setup.sh launchers`: it creates `applications/openrgb-<name>.desktop` ("OpenRGB: <Name>") and links
   it into the menu. Names with quotes, `$`, backticks or backslashes are skipped.
4. Commit the new profile and its launcher. `./openrgb/setup.sh status` shows what is still uncommitted.

Deleting a profile: the reminder points it out, and `./openrgb/setup.sh launchers` removes its launcher (the file in
`applications/` and its menu link; only launchers with `X-OpenRGB-Profile=`, never the plain "OpenRGB" entry).
Commit the removal together with the deleted profile.

## Syncing / uninstalling

- OpenRGB sometimes replaces a symlinked config file with a real one when it saves. `./openrgb/setup.sh status`
  shows that, `./openrgb/setup.sh sync` copies such files back into the repo and `install` re-links them.
- `./openrgb/setup.sh uninstall` removes the symlinks and disables the services. System files (udev rules, modules,
  kernel parameter) and the AppImage are left alone.
